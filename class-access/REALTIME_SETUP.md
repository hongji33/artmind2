# 넓은 단일 갤러리 · 디자인 공유 설치

이 브랜치는 새 구조를 검토하고 운영 규칙 게시를 기다리는 단계입니다. 코드만 배포하면 기존 규칙이 새 좌표와 디자인을 거부할 수 있으므로 아래 순서로 적용합니다.

## 서비스 운영자

1. 기존 Realtime Database를 그대로 사용합니다. 새 프로젝트나 데이터베이스를 만들지 않습니다.
2. Firebase 콘솔 → Realtime Database → 규칙에서 기존 내용을 보관하고, 이 브랜치의 루트 `realtime.rules.json` 전체로 교체해 게시합니다. Firestore 규칙은 변경하지 않습니다.
3. 오류 없이 게시된 뒤 웹앱을 배포하고 교사/학생 기기에서 새 주소로 새로고침합니다. 기존 반 번호와 회원 증명 방식은 유지하므로 이 변경 때문에 번호를 다시 설정할 필요는 없습니다. 처음 실시간 연결하는 반은 교사 화면에서 번호를 한 번 저장해야 합니다.

새 규칙이 필요한 이유는 바닥 좌표 범위(28×22), 제한된 크기의 디자인 이미지, 교사 배치 설정 저장 항목이 추가되었기 때문입니다. 학생끼리는 같은 반 정보만 읽고 본인 캐릭터만 씁니다. 교사는 본인 공간의 배치만 설정하며 학생 위치는 읽기만 합니다.

작업 환경에는 Firebase 관리자 자격이 없어 운영 규칙을 직접 게시하지 못합니다. 공식 규칙 에뮬레이터 다운로드도 네트워크 정책 403으로 차단되어 실제 규칙 검사는 실행하지 못했습니다. 콘솔 게시 후 실제 두 기기 입장과 권한을 확인해야 합니다.

## 갤러리와 배치

모든 학생은 방 번호 0의 한 공간에 있습니다. 바닥은 28×22로, 이전 12×10 전시관 하나보다 약 5배 넓습니다. 교사 화면의 반별 ‘갤러리 배치’에서 개방형/T자/U자/파티션형을 골라 저장합니다. 파티션은 같은 공간의 전시 벽이며 방을 나누지 않습니다. 배치는 접속 중인 기기에 반영됩니다.

기본 벽만으로 한 반 30점을 전시하며, 많은 기존 작품을 불러오면 필요한 전시 벽을 추가합니다. 최대 100개 조회 범위까지 자리와 연결된 통로를 검사했습니다. 임의의 벽을 드래그하는 편집기는 포함하지 않습니다.

‘전체 보기’는 갤러리 전체를, ‘내 위치’는 내 주변을 확대합니다. 30명 입장은 공간 전역의 빈 위치에 분산합니다. 내 캐릭터는 초록색 발밑 테두리와 ‘닉네임 · 나’로 표시합니다. 이름표는 충돌하지 않는 위치를 찾고 필요한 경우 연결선을 표시합니다. 화면에 자리가 부족한 이름표는 숨길 수 있습니다.

이동은 최신 수신 위치를 기준으로 다른 캐릭터 통과를 막고 기존 겹침에서는 빠져나올 수 있습니다. 네트워크 지연과 동시 이동 때문에 순간적인 겹침을 완전히 보장해서 없애는 서버 물리 엔진은 아닙니다.

## 옷과 디자인

기본 옷/색상과 직접 만든 원단, 업로드 캐릭터를 같은 반에 공유합니다. 원단은 최대 24,000자, 캐릭터는 50,000자 이내의 축소 PNG/WebP 데이터로 전송합니다. 임의 외부 이미지 URL/SVG는 허용하지 않습니다. 디자인은 바뀔 때 전송하고 이동/하트비트에는 반복 전송하지 않습니다. 패턴 해제와 기본 캐릭터 복귀도 반영합니다.

연결 종료 시 캐릭터 세션과 디자인은 같은 onDisconnect 삭제 대상입니다. 브라우저에 보관한 원단은 기존과 같이 학생 로그아웃 때 정리합니다. 교사는 학생 세션을 만들거나 인사를 보내지 않습니다.

## 검사와 운영 확인

- Node: 네 배치 각각 30/100개 작품 자리 접근, 30명 분산 배치, 캐릭터 진입 방지/겹침 탈출, 좌표 범위, 디자인 크기/형식과 이동 중 재전송 없음.
- 모의 Chromium: 분리된 두 계정의 옷/색/원단/이미지/초기화 공유, 인사·이동·퇴장; 30명+30개 작품·이름표·내 표시·U 배치 반영; 교사 설정과 관람; 휴대폰 스크롤; 감상문 작성/게시/재입장.
- 미검증: 운영 Firebase 규칙 실행과 실제 학교 기기 30대의 동시 접속. 설치 후 두 기기 검사와 학급 리허설이 필요합니다.

Spark Realtime Database는 프로젝트 전체 동시 연결 100개 한도가 있으며 여러 탭/학급도 포함합니다. 무료 전송량은 활동 시간과 디자인 사용량에 따라 달라집니다. 공식 한도: https://firebase.google.com/docs/database/usage/limits
