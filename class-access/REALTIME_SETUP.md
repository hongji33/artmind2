# 함께 보이는 캐릭터와 짧은 인사

현재는 준비된 코드와 모의 검사를 제공하는 단계입니다. 운영 Realtime Database 규칙을 적용하고 실제 두 기기 입장을 확인하기 전에는 배포 완료로 간주하지 않습니다.

## 서비스 운영자: 기존 데이터베이스 연결

새 데이터베이스를 만들지 않습니다. 사용자가 확인한 다음 주소를 `realtime-config.mjs`에 반영했습니다.

`https://artmind2-2edd4-default-rtdb.asia-southeast1.firebasedatabase.app`

Firebase 콘솔 → **Realtime Database → 규칙**에 저장소 루트의 `realtime.rules.json` 전체를 붙여넣고 게시합니다. **Firestore Database 규칙과 다른 파일/화면**입니다. 기존 RTDB 규칙을 먼저 보관합니다. 이 기능은 museum_classes / museum_members / museum_presence 세 경로만 사용하며 기존 Firestore 작품을 옮기거나 삭제하지 않습니다. 프로젝트의 익명 로그인은 유지합니다. 규칙을 공개 읽기/쓰기나 테스트 모드로 바꾸지 않습니다.

이 작업 환경은 Firebase 관리자 권한이 없어 운영 규칙을 직접 게시하지 못했습니다. 규칙 에뮬레이터도 다운로드가 네트워크 정책의 403 응답으로 막혀 실행하지 못했습니다. 콘솔 게시 시 구문 오류와 실제 권한은 설치 후 확인해야 합니다.

## 교사: 웹앱에서 최초 한 번 연결

기능 배포 후 teacher.html에서 담당 반에 **기존과 같은 번호를 한 번 입력하여 저장**합니다. Firestore의 salt/해시와 함께 RTDB의 자기 교사 공간에도 동일한 설정을 동기화합니다. 원문 번호는 저장하지 않습니다. 기존 작품은 그대로입니다. 실패하면 ‘함께보기 연결 다시 시도’를 눌러 재전송할 수 있습니다. 재시도 데이터는 현재 페이지 메모리에만 두며 로그아웃 시 제거합니다. 새로고침 뒤에는 번호를 다시 입력해 동기화합니다.

작품용 설정과 실시간 설정은 서로 다른 서비스이므로 한 트랜잭션으로 저장되지 않습니다. 작품 설정 저장 후 실시간 연결에 실패하면 이를 별도로 표시하고 재시도를 제공합니다. 처음 연결할 때는 담당 반의 번호를 먼저 저장한 뒤 반 이름/입장 허용만 변경하는 작업을 진행합니다.

그다음 **학생 링크**를 새로 복사해서 학생들에게 전달합니다. 이전 방식의 반은 `host`가 포함된 링크, 새 교사 공간의 반은 `teacher`가 포함된 링크를 사용합니다. 교사는 Firebase에 들어가거나 UID를 등록할 필요가 없습니다.

## 학생

로그아웃한 뒤 새 학생 링크에서 학반·닉네임·반 번호로 입장합니다. 온라인 전시 후 미술관에서 같은 관의 친구 캐릭터와 닉네임을 볼 수 있습니다. 옆 패널에는 학급 전체와 관별 연결 인원이 표시됩니다. 관은 자유롭게 이동하며, 특별 전시관은 같은 쪽에 있는 친구만 표시합니다.

인사는 ‘안녕 👋 / 반가워 😊 / 같이 감상하자 🎨 / 멋진 작품이야 ✨’ 네 버튼입니다. 말풍선은 약 5초, 다시 보내기는 최소 5초 간격입니다. 자유 입력 채팅·음성·채팅 기록은 포함하지 않습니다. 기본 캐릭터의 머리·옷·피부·표정은 공유하며 직접 올린 캐릭터 이미지나 원단은 기존처럼 해당 기기에만 적용합니다. 다른 캐릭터가 길을 막지는 않습니다.

나가거나 연결이 끊기면 onDisconnect로 해당 탭의 캐릭터를 제거합니다. 여러 탭은 별도 연결로 정리하고 화면에서는 같은 UID를 한 명으로 합칩니다. 끊긴 네트워크 감지는 지연될 수 있어 오래된 캐릭터는 추가로 필터링합니다.

## 범위와 사용량

이동은 약 1.2초 간격으로 바뀐 필드만 전송하고, 화면에서 위치를 보간합니다. 가만히 있으면 약 20초마다 상태를 갱신합니다. 작품 저장소인 Firestore에는 좌표/인사를 쓰지 않습니다. 실시간 연결 실패 시 기본 작품 감상은 계속할 수 있습니다.

Spark의 Realtime Database 동시 연결 한도는 프로젝트 전체 100개이며 여러 탭과 다른 학급도 포함합니다. 30명 규모를 대상으로 만들었지만 무료 전송량은 활동 시간과 수업 수에 따라 소진될 수 있습니다. 실제 학교 30대 동시 접속은 아직 검증하지 않았습니다. 운영 전 두 기기에서 같은 관 이동·인사를 확인한 뒤 학급 리허설을 권장합니다.

공식 한도: https://firebase.google.com/docs/database/usage/limits

## 보안 모델

교사는 비밀번호 Auth로 자기 UID 공간의 반 설정만 씁니다. 학생은 Firestore 입장 확인 후 같은 해시 증명으로 RTDB 회원을 생성합니다. 비밀번호 해시는 학생이 읽지 못하고, 회원은 본인만 조회하며, 다른 반/다른 교사 공간의 위치·인사를 읽을 수 없도록 규칙을 작성했습니다. 위치는 본인 연결만 쓰고 인사는 허용된 코드만 받습니다. 승인 정보는 12시간 유효하며 번호 변경은 새 입장에 적용합니다.
