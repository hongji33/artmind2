# 무료 Spark용 반 비밀번호 입장

Cloud Functions·Blaze·별도 인증 서버 없이 기존 Firebase 익명 Auth와 Firestore 보안 규칙을 사용합니다. **아직 운영 규칙과 반 설정이 적용되지 않았으며 PR #10은 설치 대기 상태입니다.**

## 관리자 한 번 설정

1. 사용자가 제공한 현재 운영 규칙에 입장 규칙을 병합한 전체 파일은 `firestore.rules`입니다. 기존 규칙을 백업한 후 Firebase 콘솔 → Firestore Database → 규칙 탭에 **전체 파일 내용**을 붙여넣고 게시합니다. 기존 작품·댓글·좋아요 규칙은 제공 원문 그대로 보존했습니다. 이후 콘솔에서 별도로 변경한 내용이 있다면 덮어쓰지 말고 다시 비교합니다. `firestore-private.fragment.rules`는 참고용 조각이며 전체 파일과 중복해서 추가하지 않습니다.
2. 규칙이 새 경로를 보호하는지 확인한 후 `password-setup.html`을 내려받아 Chrome에서 엽니다(파일 한 개로 동작하며 네트워크 전송 없음). 학반과 교사가 정한 반 비밀번호(최소 6자, 추측하기 어려운 12자 이상 권장)를 입력합니다. 이 도구는 비밀번호를 전송하지 않고 브라우저에서 임의 salt와 PBKDF2-SHA256(210,000회) 해시를 만듭니다.
3. Firebase 콘솔 → Firestore Database → 데이터에서 반마다 아래 두 문서를 등록합니다. 예시 학반은 `3-1`입니다.

| 문서 | 필드 | 형식 |
|---|---|---|
| `artmind2_class_public/3-1` | salt / iterations | string / number 210000 |
| `artmind2_class_access/3-1` | enabled / passwordHash | boolean true / string |

설정 화면의 JSON과 같은 필드를 입력합니다. 원문 비밀번호는 등록하지 않습니다. 비공개 passwordHash는 비밀번호와 같은 자격 정보이므로 채팅·공개 저장소·학생 배포 자료에 올리지 않습니다. 공개 salt와 반복 횟수에는 비밀이 없습니다.

4. 실제 SDK로 정상 입장, 틀린 비밀번호, 비활성 반, 다른 학생의 회원 문서 접근, 다른 반 전시 접근을 확인한 후 화면 변경을 배포합니다. GitHub 파일을 배포하는 것만으로 Firebase 규칙이나 학급 문서가 설치되지는 않습니다. 현재 작업 환경에는 Firebase 관리자 권한이 없습니다.

## 학생 흐름과 보안 범위

- 학년·반·닉네임·반 비밀번호 입력 → 익명 UID 생성 → 공개 salt 조회 → 브라우저 해시 계산 → 회원 문서 생성 요청 → Firestore 규칙이 비공개 해시와 비교해 승인합니다. 학생별 UID를 교사가 하나씩 승인할 필요가 없습니다.
- 다른 학생의 회원 문서 및 비공개 해시 문서는 읽을 수 없습니다. 학생은 공개 salt를 바꾸거나 자신의 승인 학급/닉네임을 사후 변경할 수 없습니다. 다른 학생은 새 UID로 입장합니다.
- 회원 문서에는 검증용 해시가 잠시 포함되고, 승인 후 즉시 필드를 제거합니다. 제거 요청이 실패해 남아도 본인만 읽을 수 있도록 보호합니다. 원문 비밀번호와 검증용 해시를 브라우저 저장소·URL에 보관하지 않습니다. 세션 표시는 UI용이며 실제 권한은 Firestore가 검사합니다.
- 같은 탭에서 수업 → 메타버스는 세션을 이어 받습니다. 로그아웃 후 같은 닉네임으로 들어와도 이전 UID의 작품 수정 권한은 복구하지 않습니다. 기존 서버 전시는 삭제하지 않습니다.
- 반 비밀번호는 공동 입장용이며 학생 개인의 신원을 증명하지 않습니다. 교사 계정/교사별 독립 관리 화면은 이 변경에 포함되지 않습니다. 교사는 Firebase 관리자 콘솔로 설정합니다.
- 이 방식에는 서버의 UID/IP별 비밀번호 시도 제한이 없습니다. 추측하기 어려운 비밀번호를 사용하고 수업 외 공유를 피해야 합니다. Spark 무료 쿼터를 모두 쓰면 입장·읽기·저장이 중단될 수 있습니다. 30명 접속에 별도 결제를 추가하지 않지만 실제 학교 네트워크·운영 사용량은 검증해야 합니다.
- 비밀번호 변경/반 비활성화는 새 입장을 막습니다. 이미 승인된 익명 UID의 권한을 회수하려면 해당 회원 문서도 관리자가 제거해야 합니다.

## 검사

```sh
node --test class-access/password-crypto.test.mjs tests/layout.test.mjs
python tests/class_entry.py
python tests/lesson_entry.py
python tests/clean_session.py
python tests/browser_test.py
```

Web Crypto와 Node PBKDF2 결과 일치(한국어 포함), 잘못된 입력, 실제 수업·로그아웃·게시·갤러리·교사용 설정 UI를 검사합니다. 브라우저 검사는 모의 Firebase를 사용합니다.

추가 보안 규칙 검사는 실제 프로젝트 대신 격리된 에뮬레이터를 사용합니다.

```sh
cd class-access
npm ci
npx --yes firebase-tools@14.22.0 emulators:exec --project demo-artmind-free --config emulator.json --only firestore 'npm run test:rules'
```

전체 병합 규칙을 대상으로 30명 동시 회원 생성, 같은 반 전시 조회/게시/댓글/좋아요 및 다른 반 접근 차단, 잘못된 비밀번호/비활성·미등록 반, 다른 UID 접근, 학급 변조, 비공개 해시 열람 차단 및 해시 정리를 검사하도록 작성했습니다. 에뮬레이터 다운로드가 실행 환경의 네트워크 정책으로 차단되어 이 검사는 **아직 실행하지 못했습니다.** 운영 보안 규칙과 실제 30대 크롬북 동시 접속도 미검증입니다. `tests/emulator.rules`는 검사용 시작 규칙이며 운영 규칙으로 배포하면 안 됩니다.
