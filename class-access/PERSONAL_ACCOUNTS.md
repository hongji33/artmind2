# 학생 개인번호 · 작성 복원 · 교사 확인/초기화

## 배포 전 운영자가 할 일

개인번호 코드와 모의 검사는 준비됐으며, 운영 규칙 적용을 기다리는 단계입니다. 규칙 적용 전에는 배포하지 않습니다. 앞서 적용한 넓은 갤러리 규칙만으로는 개인 계정 기록과 초안 저장을 허용하지 않습니다.

1. Firebase 콘솔 → **Firestore Database → 규칙**에 이 버전의 `class-access/firestore.rules` 전체를 게시합니다. 담당 교사만 학생 개인번호 기록을 조회하고, 학생은 본인 작성 내용을 저장·조회하며, 동일 ID의 반 비밀번호 재인증을 허용합니다.
2. **Realtime Database → 규칙**에는 이 버전의 루트 `realtime.rules.json` 전체를 게시합니다. 같은 학생 ID가 다시 로그인할 때 입장 증명 시간을 갱신하도록 수정했습니다.
3. 두 규칙이 오류 없이 게시된 뒤 웹앱을 배포합니다. 교사/학생 화면을 새로 열고 새 QR을 사용합니다. 이메일/비밀번호와 익명 제공자는 이미 사용하는 설정을 유지합니다. 별도 Apps Script나 Cloud Functions는 사용하지 않습니다.

작업 환경에는 Firebase 관리자 권한이 없어 규칙을 직접 게시하지 못했습니다. 에뮬레이터도 다운로드 403으로 실제 규칙 검사를 실행하지 못했으므로 운영 규칙 적용 후 실제 계정 검사가 필요합니다.

## 학생

- 처음에는 반별 QR에서 ‘처음 · 개인번호 만들기’를 선택하고 반 입장 번호 4자리와 본인 개인번호 6자리를 입력합니다. 닉네임은 한 교사의 한 반 안에서 계정 이름으로 사용하므로 중복 등록할 수 없습니다.
- 학생 인증은 현재 탭의 세션에 보관합니다. 탭을 닫았다가 다시 열면 개인번호로 로그인하며, 서버에 저장한 작성 내용은 유지됩니다. 교사 인증은 별도 앱이므로 그대로 유지합니다.
- 다음부터는 같은 반·같은 닉네임·개인번호로 ‘다시 로그인’을 선택합니다. 이메일 주소를 직접 입력하거나 이메일을 소유할 필요는 없습니다. 앱은 교사/반/닉네임의 해시로 내부 Auth 식별 주소를 만듭니다.
- 작성한 관찰/감정/성찰/감상문은 본인 계정으로 저장합니다. 자동 저장은 변경분만 일정 간격으로 보내며, 저장·전시·로그아웃 시에는 즉시 확인합니다. 저장 실패 시 로그아웃을 멈춥니다. ‘개인 계정에 저장됨’을 확인하고 나가세요. 미완성 내용도 파일로 내려받을 수 있습니다.
- 다시 로그인하면 작성 내용을 복원합니다. 온라인 전시도 동일 Auth UID 문서를 수정하므로 새 작품을 중복 생성하지 않습니다.
- 학생은 이 수업 전용 개인번호를 사용합니다. 요청한 운영 방식에 따라 담당 교사가 그 번호를 확인할 수 있다는 안내를 등록 화면에 표시합니다.

## 교사

‘학생 개인번호 관리’에서 반을 고르고 학생을 불러옵니다. 번호는 가려져 있으며 ‘보기’로 확인합니다. QR 창을 열면 표시했던 번호를 다시 가립니다.

‘초기화’에서 새 숫자 6자리를 지정합니다. 학생에게 새 번호를 알려주면 되고 기존 작성 내용과 작품 ID는 유지됩니다. 교사 본인의 로그인은 유지합니다. 내부적으로 별도의 메모리 Auth 앱에서 해당 학생 인증/번호 변경을 수행하고 곧바로 로그아웃·정리합니다.

Firebase Auth 번호 변경과 교사 기록 저장은 한 트랜잭션이 아니므로, 임시 후보를 먼저 기록하고 성공 후 확정합니다. 확정 기록 저장에 실패해도 새 번호 후보를 남겨 다음 재설정에서 복구할 수 있습니다. 화면이 ‘보관 정보 확인 필요’라고 안내하면 표시된 새 번호를 먼저 기록하고 연결이 돌아온 뒤 다시 확인합니다.

개인번호는 교사가 원문을 확인할 수 있는 전용 기록이며 해시만 저장하는 방식이 아닙니다. `student_accounts`는 담당 교사만 읽으며 다른 학생·다른 교사에게는 허용하지 않습니다. 학생은 본인의 인증된 UID/이메일과 반 회원 증명으로 본인 기록만 씁니다. 개인번호는 작품·감상문 JSON이나 공개 전시 문서에 넣지 않습니다.

## 기존 익명 자료

아직 같은 기기에 익명 학생으로 로그인돼 있으면, 로그아웃하기 전에 상단 ‘개인번호 만들기’를 사용합니다. 기존 익명 UID에 이메일 자격을 연결해 작품 소유권을 유지합니다. 게시한 글만 남아 있으면 제목과 감상문을 불러오며 이전 관찰 기록은 임의로 만들지 않습니다.

이미 익명 상태에서 로그아웃해 이전 UID를 잃은 글은 닉네임만으로 자동 소유권 연결하지 않습니다. 다른 학생이 같은 닉네임을 입력해 글을 가져갈 수 있기 때문입니다. 기존 공개 전시는 같은 반에서 계속 볼 수 있습니다.

등록 인증은 됐지만 교사 계정 기록 저장에 실패한 경우에는 등록을 반복하지 말고 방금 만든 번호로 ‘다시 로그인’을 선택해 기록 저장을 재시도합니다.

## 검증

모의 SDK 브라우저 검사: 확인번호 불일치, 등록, 잘못된 번호, 동일 UID 재로그인, 작성 복원, 공개 동의, 기존 전시 수정, 번호 가림/보기/초기화, 초기화 도중 Auth/기록 저장 실패와 재시도, 교사 세션 유지, 익명 UID 전환, 기록 저장 중단 후 재로그인 복구, 저장 실패 시 로그아웃 중단/취소/실패 복원을 확인했습니다.

`class-access/tests/personal.rules.test.mjs`는 담당 교사 전용 개인번호 조회, 다른 교사/학생 차단, 본인 초안 읽기/쓰기, 동일 회원 재인증을 검사하도록 준비했습니다. 운영 규칙 또는 에뮬레이터에서 실행하기 전에는 보안 검사 통과로 간주하지 않습니다.
